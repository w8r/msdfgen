  <name>Task 2: Implement WGSL shaders with visualization modes</name>
  <files>demo/shaders/msdf.wgsl, demo/shaders/types.ts</files>
  <behavior>
    - Vertex shader: Transform instanced quad corners using per-character model matrix and view-projection uniform
    - Vertex shader: Map quad UV (0-1) to atlas UV bounds from instance data
    - Fragment shader: Sample atlas texture and compute median distance from RGB channels
    - Fragment shader: Mode 0 (rendered): Apply derivative-based smoothstep with median distance and user color
    - Fragment shader: Mode 1 (raw): Display raw RGB channels directly (no median computation)
    - Fragment shader: Mode 2 (heatmap): Map distance to hot-to-cold gradient (red → yellow → green → blue)
    - All modes use same vertex shader, mode branching only in fragment shader
  </behavior>
  <action>
Create demo/shaders/msdf.wgsl with:
- Vertex shader: VertexInput (quad corner position + texCoord), InstanceInput (mat4 model + vec4 uvBounds)
- Uniforms: viewProjection matrix (group 0, binding 0), atlas texture (binding 1), sampler (binding 2), uniforms struct with color vec4 and mode u32 (binding 3)
- Fragment shader: median() function, three mode branches (rendered with dpdx/dpdy derivatives for smoothstep width, raw RGB, heatmap gradient)
- Use OpenGL Y-flip UV convention (matches Phase 2 atlas uvBounds)

Create demo/shaders/types.ts with TypeScript interfaces matching WGSL layout:
- VertexInput, InstanceInput, UniformData types for CPU-side buffer creation
- Helper functions for buffer layout calculations (stride, offsets)

Follow patterns from RESEARCH.md sections "Pattern 1: MSDF Rendering Pipeline" and heatmap color mapping.
  </action>
