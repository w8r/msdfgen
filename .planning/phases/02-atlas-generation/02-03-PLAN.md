<task type="auto">
  <name>Task 1: Reduce default glyph size for performance</name>
  <files>src/atlas/AtlasGenerator.ts</files>
  <action>
Reduce DEFAULT_CONFIG.glyphSize from 32 to 24 pixels. This is the most impactful single-variable change: reducing dimensions by 25% should yield approximately 44% fewer pixels to process per glyph.

Rationale from research:
- 32px glyph = 1024 pixels per glyph × 3 channels = 3072 distance calculations
- 24px glyph = 576 pixels per glyph × 3 channels = 1728 distance calculations
- Reduction: ~44% fewer distance calculations per glyph
- Expected speedup: ~360ms × 0.56 ≈ 202ms (measured improvement, still 2x over 100ms target)
- This validates pixel-reduction approach before more complex optimizations

**Why 24px specifically:**
- Research suggests common MSDF atlas sizes: 16px (low quality), 24px (balanced), 32px (high quality), 48px (premium)
- 24px provides good quality-to-performance tradeoff
- User can override to 32px if quality is more important than performance
- This is an experimental first step, not a guarantee of reaching <100ms

**Implementation:**
1. Change line 16 from `glyphSize: 32,` to `glyphSize: 24,`
2. Update JSDoc comment (line 49) to reflect new default: `@param config.glyphSize - Size of each glyph in pixels (default: 24)`
3. Update JSDoc example (line 60) to show `glyphSize: 24,`
4. Do NOT change distanceRange (keep at 4px) - maintains ~17% margin at 24px size

**What to avoid:**
- Do NOT reduce glyphSize below 24px - quality degradation becomes noticeable
- Do NOT change distanceRange proportionally - 4px is appropriate for both 24px and 32px
- Do NOT add complex configuration logic - keep defaults simple
